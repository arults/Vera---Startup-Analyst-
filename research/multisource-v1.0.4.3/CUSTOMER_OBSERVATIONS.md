# Customer observation extension v1 (local candidate)

ID: vera.multisource.customer-observations.v1

This additive extension leaves POLICY.md v1.1.0 bytes unchanged. New customer claims require both policies, new exact extension hash acknowledgements, independent semantic review and source review, and the existing operator-controlled reviewer registry. No legacy review is transferred. Public methodological JEV supports the taxonomy only; it is not exact code approval.

customer_project_observation records an attributed customer/project report. customer_product_use records attributed customer use of a named product at a named site. Neither is issuer operating_activity, survival, a terminal event, financing, investor return or evidence of activity on the publication day. Installed equipment can remain in use after its supplier ceases operation. Distinct sites are distinct observations, not replications of an identical event.

customer_subject binds customer ID/name, company ID, project/product, site and relationship basis. Each evidence item carries customer_attribution with the same customer/company/project/site, original witness, factual origin, customer_or_project_party role, competence rationale, relationship disclosures, correction disposition and source-specific report date. Primary customer_project_report sources must declare customer_project_party relationship. Independent reporting remains secondary, requires editorial authority assessment, and must attribute selected testimony to the customer; issuer quotes printed in journalism are not customer testimony. Retain shared funding, affiliations, corrections and conflicting evidence in the source snapshot. A university customer must not be relabelled as the issuer.

The initial extension deliberately supports only time.kind unknown. on/start/end/event_time/event_timezone/censor_date may not contain event precision. A known source publication date is required per evidence item and labelled source_publication_only; it never supplies event time, censor time or historical availability. A common claim report_date, if present, must match every evidence item. An installation month or other historical context is not the selected observation time. Future extensions for explicit customer event dates require separate provenance design.

All identity, original-source inspection, original/capture hashes, factual origins, correction/conflict, contradiction, source-depth, scoped contextual closure and reviewer-authority gates remain in force. The extension adds positive semantic checks for customer scope, unknown event time and corrections/conflicts, bound to this exact file hash through predicate_review and claim digest. Source review additionally checks this extension hash, exact customer claim IDs and authority/temporal scope. Every participant acknowledges this extension hash. Hashes do not authenticate people or establish semantic truth; independent human/agent review through the operator-controlled registry is indispensable.

All outputs remain augmented research observations, and the new report explicitly emits no issuer-survival, operating, financing or return result. State transition and point censor are null; estimator/numerical-prior eligibility is false. No native outcome, denominator or clock change is supported. Structured attempts to promote customer claims or retype their customer contract are invalid. Natural-language entailment and deceptive relabelling remain independent semantic review responsibilities, not automated text understanding.

Actual Ecotone observations remain held pending separate exact-data/source/semantic review, scoped research adequacy, policy acknowledgement and authentic root registry. Existing outside-source verdict is context, not an executable approval. No external calls, JEV submissions, publication or canonical mutations are part of this candidate.

Revision 1.0.4.1 enforces calendar dates in YYYY-MM-DD form (including real-date validity). Basic and week ISO forms are not valid report dates. Scoped primary_customer origin classification requires a nonempty set of selected claims using that source through either evidence or identity; every such claim must be customer-scoped. Identity-only sources cannot loosen existing issuer claims.
