# Operating uncertainty numerical guards v0.1.0

Additive, synthetic-only candidate for the explicit-history operating-occupancy
reporter. No empirical records, rates, population changes, source admission,
promotion or production/plugin integration are included.

## Concrete failure and bounded repair

Five distinct-company PRE→POST histories, observed through month 6 with
success transitions at months 1–5, have exact operating occupancy 1 at month 5.
The frozen reporter returns raw point `1.0000000000000002`, a bootstrap interval
`(1.0, 1.0000000000000002)` and an inverted analytic interval
`(1.0000000000000002, 1.0)` (100 draws, seed 73).

The same issue occurs away from a boundary. When each of five companies has
one continuing operating round and one closure round, every whole-company
resample has exact occupancy 1/2. Floating-point differences create a spurious
nonconstant bootstrap distribution and a machine-scale analytic interval.

The new module delegates to the unchanged frozen estimator, cluster sampler
and analytic derivative. It only guards reported uncertainty:

- Declare a 64-ulp absolute probability roundoff tolerance, consistent with the
  separate first-success uncertainty component.
- Distinguish exact bootstrap degeneracy from a complete distribution whose
  spread is at most that tolerance. The latter receives a withheld numerical
  degeneracy status instead of an informative interval.
- Withhold analytic intervals at machine-scale boundary points or standard
  errors. Unsupported risk, insufficient clusters and existing dispositions
  remain in force.
- Clip only final percentile bounds after checking every available raw value
  lies within the declared roundoff extension of [0,1]. Raw points, draws,
  company choices, round identities, scores and covariance are preserved.
- Compare intervals only when both guarded intervals are available.

The absolute tolerance is a conservative reporting safeguard. It does not prove
mathematical zero variation: genuinely nonzero variation below machine-scale
resolution may also be withheld. It is not an empirical adequacy threshold,
confidence-coverage claim, or change to the equal-round/company-cluster target.

Nonfinite or materially out-of-range upstream point/draw values fail closed
with `ValueError`; they are not clipped into plausible probabilities. That
exception returns no report. Original frozen reports and source files remain
available for diagnosis. Existing declared undefined bootstrap draws continue
to be retained with their original failure reasons and null degeneracy.

## Why additive

The baseline modules are bound by the existing first-success uncertainty
validator and the frozen baseline package. Changing them in place would break
those dependencies. All frozen Python source/test bytes remain identical to
commit `de1f7b9b375618cf92fe12339e420cf07a0f48f1`. The new dependency manifest
pins all ten imported baseline source/test files to their Git blob hashes.
There is no automatic caller switch: consumers must explicitly import the new
guard module. Existing legacy imports retain the documented defect until a
separately reviewed integration occurs.

## Reproduce

Python 3.10+ standard library only. From repository root:

    python -I -B research/operating-uncertainty-guards-v0.1.0/validate.py
    python -I -B research/operating-uncertainty-guards-v0.1.0/test_isolated_validation.py

Absolute script paths work from unrelated working directories. The validator
checks frozen Git blob hashes before importing tests. It runs 74 frozen tests
plus 19 candidate tests: 93 tests total. The separate three subprocess tests
exercise relocated isolated validation with a hostile PYTHONPATH, unchanged
source bytes/no generated bytecode, tampered dependency rejection, and missing
dependency rejection. Their internal rerun is not additional independent test
coverage.

Candidate checks include 90 exact-rational synthetic history/horizon cases,
1,080 independently reconstructed whole-company draws, 46 constant-statistic
size/configuration cases, boundary and interior regressions, unchanged regular
intervals, tied events/censors, initial terminal mass, unequal company sizes,
unsupported/undefined/NOT_RUN precedence, extreme confidence levels, and
fail-closed nonfinite/materially invalid upstream values. Reused baseline tests
and the separate first-success validator overlap and must not be added as
independent totals.

## Explicit import

Add this directory and the frozen `explicit-history-statistics-v0.2.0`
directory to the import path, then import `operating_uncertainty_report` from
`operating_uncertainty_guards`. The required disagreement threshold, horizon,
histories, seed, requested count and confidence semantics are unchanged.

This candidate does not qualify real histories, complete endpoint/source
semantics, validate censoring assumptions, establish nominal coverage, or
complete scientific Phase 1D. It has no external dependencies or service calls.
